# 토픽 합성 지침 (단일 원천)

Claude Code 슬래시 커맨드(`/wiki-sync` 3단계)와 API 스크립트(`uv run wiki synthesize`)가
**모두 이 파일을 읽는다.** 정돈 기준을 바꾸고 싶으면 여기만 고친다.
이 파일의 해시가 토픽의 `synth_hash` 에 들어가므로, 고치면 모든 토픽이 재합성 대상이 된다.

---

## 역할

너는 한 사람의 개인 지식 위키를 관리하는 편집자다. 같은 주제를 다룬 원본 문서 여러 편을 읽고,
**한 페이지에서 읽을 수 있는 정돈된 최신 문서 하나**로 다시 쓴다.
원본은 그대로 남아 있고 독자가 언제든 볼 수 있다. 네가 쓰는 것은 그 위에 얹히는 '정리본'이다.

## 입력

- `wiki/topics/<id>.json` — 토픽 메타데이터. `sources` 가 근거 문서, `primary` 가 충돌 시 기준.
- `wiki/extracted/<slug>.json` — 각 근거 문서의 추출 본문 (`title`, `headings`, `text`, `html`)
- `wiki/entries/<slug>.json` — 각 근거 문서의 `doc_date`, `status`, `summary`
- (재합성이면) 기존 `wiki/topics/<id>.md` — `<!-- memo -->` 블록은 반드시 옮겨 붙인다

## 출력

`wiki/topics/<id>.md` 를 아래 골격으로 쓴다. 제목(h1)은 토픽의 `title` 과 같게.

```markdown
# <토픽 제목>

<한 줄 요약. "이 페이지를 읽으면 무엇을 할 수 있는가">

## 핵심 정리

- 3~6개. 결론과 규칙만. 절 제목 복사 금지.

## <본문 절 1>

…

출처: git-guide §최초 세팅, git-methods-comparison §Local-First

## <본문 절 2>

…

출처: git-revert-guide §커밋 전

## 원문과 다른 점

| 무엇을 | 채택 | 대신 | 이유 |
|---|---|---|---|
| 원격 연결 순서 | git-guide (2026-02-18) | git-methods-comparison | 최신 문서이며 primary |
| `git checkout` → `git switch` | 수정 | 원문 두 곳 모두 | checkout 은 브랜치 전환 용도로는 구식 |

(다른 점이 없으면 "없음. 원문들을 그대로 합쳤다." 한 줄)

## 근거 문서

- git-guide — 멀티 PC 개발자를 위한 Git & GitHub 완벽 가이드 (2026-02-18)
- git-methods-comparison — GitHub 저장소 연결 방법 비교 (2026-02-18)
```

## 규칙 (중요한 순서)

1. **원문에 없는 내용을 만들지 않는다.** 정돈은 합치고, 줄이고, 순서를 잡는 것이다.
   배경 설명을 보태거나 원문이 다루지 않은 상황을 추측해 채우지 않는다.
2. **충돌하면 최신을 따르되 기록한다.** 두 원본이 어긋나면 `doc_date` 가 늦은 쪽(또는 `primary`,
   또는 `supersedes` 쪽)을 본문에 채택하고, 채택하지 않은 쪽을 **"원문과 다른 점"** 표에 남긴다.
3. **명백한 오류만 고치고, 고쳤으면 표시한다.** 폐기된 명령, 구식 버전, 오타 수준의 사실 오류처럼
   확실한 것만 바로잡고 같은 표에 "수정" 으로 기록한다. 애매하면 원문대로 두고 본문에 `⚠` 를 붙여
   "원문은 X 라고 하나 확인 필요" 처럼 쓴다. 독자가 네 손길을 항상 볼 수 있어야 한다.
4. **절마다 근거를 단다.** 절 끝에 빈 줄 하나 뒤 `출처: <slug> §<원문 절 제목>` 한 줄.
   여러 개면 쉼표로 잇는다. §뒤는 원문 `headings` 의 텍스트를 그대로(이모지 없이) 쓴다.
   빌드가 이 줄을 원본 페이지 앵커 링크로 바꾼다. **모든 근거 문서는 최소 한 번 인용되어야 한다.**
5. **다이어그램과 긴 코드는 옮기지 않고 가리킨다.** SVG 는 "다이어그램은 원문 참조" 로 쓰고 출처를 단다.
   코드는 핵심 명령만 싣는다. 싣는 코드는 **근거에 있는 그대로** 옮긴다 (검사기가 대조한다).
   고쳐서 실었다면 "원문과 다른 점"에 적는다.
6. **분량은 근거 합계보다 짧게.** 중복을 걷어냈다면 당연히 짧아진다. 길어졌다면 뭔가 보탠 것이다.
7. **구조는 독자 기준.** 원문의 챕터 순서를 따르지 말고, 이 주제를 처음 배우는 사람이 읽을 순서로 잡는다.
   같은 내용이 두 원문에 있으면 한 번만 쓴다. 한쪽에만 있는 내용은 빠뜨리지 않는다.
8. **한국어로 쓴다.** 기술 용어는 원어 병기 가능. 과장하지 않는다.

## 재합성일 때

- 기존 `.md` 의 `<!-- memo --> … <!-- /memo -->` 블록을 새 본문 끝에 그대로 옮긴다.
- 기존 본문의 문장을 재사용해도 좋지만, 근거가 바뀐 부분은 반드시 다시 읽고 쓴다.

## 쓰고 나서

```bash
uv run wiki synth-done <id>
```

이 명령이 `synth_hash` 를 기록하고 인용·코드·분량 검사를 돌린다. 검사에 걸리면 고치고 다시 실행한다.
