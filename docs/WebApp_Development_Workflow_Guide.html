AI 기반 웹 앱 개발
워크플로우 가이드

Claude Code + Next.js + Supabase + Vercel

비개발자를 위한
단계별 실행 가이드
v1.0 · 2026.03
이 문서는 AI 코딩 도구(Claude Code)를 활용하여 웹 앱을 기획부터 배포까지 완성하는 전체 과정을 정리한 것입니다. 개발 경험이 없어도 각 단계의 목적과 행동을 이해하고 따라할 수 있도록 구성했습니다. 총 10단계이며, 핵심은 "좋은 기획 문서 → AI에게 정확한 지시 → 반복 수정"입니다.
1
아이디어 구상
기획
만들고 싶은 앱의 목적, 사용자, 핵심 기능을 자유롭게 정리한다. 완벽할 필요 없다.
핵심 질문
누가 쓰는가? 어떤 문제를 해결하는가? 가장 중요한 기능 3가지는?
도구
메모장, 노션, 또는 Claude 대화
2
플랜 문서 작성
기획
Claude와 대화하며 아이디어를 구체적인 개발 계획서로 발전시킨다. DB 구조, API 설계, 페이지 구조, 스타일 가이드까지 포함해야 한다.
산출물
개발 계획서 (.md) — 기술 스택, DB 스키마, API 명세, 페이지 구조, 디렉토리 구조, 스타일 가이드 포함
3
Supabase 셋업
셋업
코드 생성 전에 Supabase 프로젝트를 먼저 만들어둔다. DB 테이블은 코드 생성 후에 적용한다.
Supabase 가입
supabase.com 가입 → 새 프로젝트 생성 → 리전은 Northeast Asia (Tokyo) 선택
API Key 확보
Settings → API 에서 Project URL, anon key, service_role key 복사해 둔다
4
환경 변수 설정
셋업
Supabase에서 발급받은 Key를 프로젝트에 연결한다. .env.local 파일에 작성하며, 이 파일은 절대 GitHub에 올리지 않는다.
필요한 값
NEXT_PUBLIC_SUPABASE_URL · NEXT_PUBLIC_SUPABASE_ANON_KEY · SUPABASE_SERVICE_ROLE_KEY · NEXT_PUBLIC_APP_URL (로컬에서는 http://localhost:3000, Vercel 배포 후 실제 URL로 변경)
5
Claude Code로 코드 생성
개발
플랜 문서를 기반으로 작성한 프롬프트를 Claude Code에 전달한다. Claude Code가 프로젝트의 모든 파일(API, 페이지, 컴포넌트, 설정)을 자동 생성한다.
입력
개발 프롬프트 (.md) — DB 스키마, API 명세, 페이지 동작, 스타일 규칙 포함
출력
전체 프로젝트 파일 (API Routes, 페이지, 컴포넌트, 유틸리티, 설정 파일)
6
DB 마이그레이션 적용
셋업
Claude Code가 생성한 SQL 파일(테이블, 인덱스, RLS 정책 등)을 Supabase에 적용한다. DB 구조가 준비되어야 로컬에서 앱이 정상 동작한다.
적용 방법
Supabase 대시보드 → SQL Editor → 프로젝트 내 .sql 파일 내용을 붙여넣기 → Run
확인
Table Editor에서 테이블 생성 확인. 에러 시 Claude Code에 메시지를 전달하여 수정
# 프로젝트 내 마이그레이션 파일 위치 예시
cat supabase-migrate.sql
# → 출력된 SQL을 Supabase SQL Editor에 붙여넣기 후 Run
7
로컬 실행 테스트
개발
환경 변수와 DB가 모두 준비된 상태에서 앱을 실행하여 정상 동작하는지 확인한다.
실행 명령
npm install → npm run dev → 브라우저에서 localhost:3000 접속
확인 항목
  • 이벤트 생성 → QR 표시
  • QR 스캔 → 참여 등록
  • 관리 URL → 명단 확인
  • 모바일 화면 레이아웃
⟳
수정 · 반복
반복
완성될 때까지 반복
테스트에서 발견한 문제나 개선사항을 Claude Code에 전달하여 수정한다. "이 버튼이 모바일에서 잘려요", "QR코드가 안 보여요" 등 구체적으로 설명할수록 정확한 수정이 된다. Step 5→7을 문제가 없을 때까지 반복한다.
8
GitHub 저장소 생성
배포
코드를 올릴 빈 저장소를 GitHub에 먼저 만든다. README 등 초기 파일은 추가하지 않는다.
절차
github.com 로그인 → 우측 상단 + → New repository
설정
Repository name 입력 · Private 선택 · README, .gitignore 체크 해제 (빈 상태) → Create
# 프로젝트 폴더에서 Git 초기화
git init
9
GitHub 푸시
배포
완성된 코드를 GitHub 저장소에 업로드한다. 이후 모든 변경 이력이 여기에 기록된다.
# 모든 파일을 스테이지에 올리기
git add .
# 첫 번째 커밋
git commit -m "Initial commit"
# 브랜치 이름을 main으로 변경 (Git 기본값이 master일 수 있으므로)
git branch -M main
# GitHub 주소를 origin이라는 이름으로 연결
git remote add origin https://github.com/내이름/프로젝트.git
# GitHub 서버로 전송 (-u는 기본 연결 설정, 최초 1회만)
git push -u origin main
이후 변경사항 업로드 (2회차부터)
git add . → git commit -m "변경 내용" → git push (간단해짐)
10
Vercel 배포
배포
Vercel에서 GitHub 저장소를 연결하면, 이후 코드를 push할 때마다 자동으로 배포된다. 환경 변수를 Vercel 대시보드에도 동일하게 등록해야 한다.
초기 설정 (1회)
Vercel 가입 → GitHub 저장소 Import → 환경 변수 등록 → Deploy
이후
git push만 하면 자동 배포. 별도 작업 없음.
⚠ 배포 후 필수 — Supabase Site URL 등록
배포 완료 후 생성된 URL (예: https://프로젝트.vercel.app)을 Supabase 대시보드 → Authentication → URL Configuration → Site URL에 등록한다. Supabase Auth(로그인, OAuth 등)를 사용하는 경우 이 설정이 없으면 인증 리다이렉트가 실패한다. 또한 Redirect URLs에도 동일 URL을 추가해 둔다.

💡 비개발자를 위한 핵심 팁

  • 가장 중요한 단계는 Step 2 (플랜 문서)이다. AI에게 주는 지시가 구체적일수록 결과물의 품질이 올라간다.
  • 프롬프트는 한국어로 작성해도 된다. 기술 용어만 영문으로 유지하면 충분하다.
  • 한 번에 완성되는 경우는 드물다. 수정 요청은 자연어로 — "이 버튼 색상을 빨간색으로 바꿔줘" 처럼.
  • .env.local 파일에는 비밀키가 들어있다. 절대 외부에 공유하지 않는다.
  • Vercel 배포 후 문제가 생기면 Vercel 대시보드 > Deployments > Logs에서 에러를 확인할 수 있다.
