Remote-First vs Local-First

GitHub 저장소를 먼저 만들고 가져오는 방법과, 로컬에서 시작해서 GitHub에 올리는 방법을 단계별로 비교합니다.

💻 방법 B: Local-First 내 PC에서 시작 → GitHub에 연결

Chapter 00

두 방법의 흐름 한눈에 보기

같은 목표(로컬 코드 ↔ GitHub 연결)를 달성하지만, 시작점이 다릅니다.

🅰️ 방법 A — Remote-First (GitHub → 내 PC)

GitHub 웹사이트에서 저장소를 먼저 만들고, 내 PC로 가져온 뒤 코드를 넣는 방식입니다.

GitHub에서
Repo 생성
→
git clone으로
내 PC에 복제
→
폴더 안에
코드 작성
→
add → commit
→ push
시작점: GitHub (원격) → 로컬로 이동

🅱️ 방법 B — Local-First (내 PC → GitHub)

내 PC에 이미 프로젝트 폴더와 코드가 있고, 이를 나중에 GitHub에 연결하는 방식입니다.

내 PC에서
코드 작성
→
git init으로
Git 초기화
→
GitHub에서
빈 Repo 생성
→
remote add
→ push
시작점: 내 PC (로컬) → GitHub에 연결
Chapter 01 · Method A

Remote-First: GitHub에서 먼저 만들고 Clone

"빈 땅을 먼저 확보한 뒤, 그 위에 집을 짓는" 방식입니다. 새 프로젝트를 처음부터 시작할 때 가장 깔끔합니다.

A-1

🌐 GitHub에 저장소 생성 (옵션 선택 가능)

github.com에 로그인 → 오른쪽 상단 [+] → New repository

  • Repository name: 프로젝트 이름 입력
  • Public / Private: 원하는 공개 범위 선택
💡
Remote-First의 장점이 여기서 나옵니다

이 방법에서는 Add a README file, .gitignore template, License를 체크해도 됩니다. GitHub가 자동으로 기본 파일들을 생성해주므로, clone 받으면 즉시 정리된 프로젝트 구조가 완성됩니다.

Create repository 버튼을 클릭합니다.

A-2

📥 내 PC로 Clone (복제)

생성된 저장소 페이지에서 초록색 Code 버튼 → HTTPS 주소를 복사합니다.

Terminal 
# 원하는 작업 디렉토리로 이동
cd ~/projects

# GitHub 저장소를 내 PC에 복제
git clone https://github.com/내이름/프로젝트.git

# 생성된 프로젝트 폴더로 이동
cd 프로젝트

이 시점에서 폴더 안에는 GitHub에서 생성한 README.md, .gitignore 등이 이미 있습니다. 그리고 Git 초기화 + 원격 주소 연결이 이미 완료된 상태입니다.

A-3

⌨️ 코드 작성 & 첫 Push

이제 이 폴더 안에서 코딩을 시작하면 됩니다.

Terminal 
# 코드를 작성한 뒤...

# 1. 변경된 파일 담기
git add .

# 2. 커밋
git commit -m "feat: 프로젝트 초기 구조 설정"

# 3. GitHub에 올리기
git push
✨
clone 했으므로 remote add, branch -M 등이 필요 없습니다

clone 시 Git이 자동으로 origin 주소를 연결하고, 기본 브랜치도 main으로 설정해줍니다. 바로 git push만 하면 됩니다.

전체 요약

📋 방법 A 전체 명령어 (3줄 요약)

Method A — 전체 과정 
# ① GitHub 웹에서 저장소 생성 (README, .gitignore 체크 가능)

# ② 내 PC로 가져오기
git clone https://github.com/내이름/프로젝트.git
cd 프로젝트

# ③ 코딩 후 올리기 (이게 전부!)
git add .
git commit -m "Initial code"
git push
Chapter 02 · Method B

Local-First: 내 PC에서 시작 후 GitHub에 연결

"이미 지은 집에 주소를 등록하는" 방식입니다. 코드가 이미 있을 때 사용합니다.

B-1

💻 내 PC에서 Git 초기화

이미 코드가 있는 프로젝트 폴더에서 Git을 활성화합니다.

Terminal 
# 프로젝트 폴더로 이동
cd ~/projects/내프로젝트

# Git 초기화 (.git 폴더가 생성됩니다)
git init
B-2

📝 .gitignore 생성 (중요!)

첫 커밋 전에 반드시 .gitignore를 만들어야 합니다. 한 번 올라간 파일은 나중에 .gitignore에 추가해도 이미 추적됩니다.

.gitignore 생성 
# .gitignore 파일 생성 후 편집
# 최소한 아래 내용은 넣어주세요:
.venv/
__pycache__/
.env
node_modules/
data_*/
.DS_Store
⚠️
방법 A와의 차이점

방법 A에서는 GitHub가 .gitignore 템플릿을 자동 생성해주지만, 방법 B에서는 직접 만들어야 합니다. 이 단계를 빠뜨리면 .venv/ 같은 거대한 폴더가 GitHub에 올라갈 수 있습니다.

B-3

📦 첫 커밋 만들기

Terminal 
# 모든 파일을 스테이지에 올리기
git add .

# 첫 번째 커밋
git commit -m "Initial commit"
B-4

🌐 GitHub에 빈 저장소 생성

GitHub 웹사이트에서 새 저장소를 만듭니다.

🚨
반드시 "빈 저장소"로 만들어야 합니다!

Add a README, .gitignore, License 체크박스를 모두 해제하세요. 로컬에 이미 커밋이 있는데 GitHub에도 커밋이 있으면, 두 기록이 달라서 push 시 에러가 발생합니다.

생성 후 나타나는 HTTPS 주소를 복사합니다.

B-5

🔗 원격 주소 연결 & Push

Terminal 
# 브랜치 이름을 main으로 변경 (Git 기본값이 master일 수 있으므로)
git branch -M main

# GitHub 주소를 origin이라는 이름으로 연결
git remote add origin https://github.com/내이름/프로젝트.git

# GitHub 서버로 전송 (-u는 기본 연결 설정, 최초 1회만)
git push -u origin main
전체 요약

📋 방법 B 전체 명령어

Method B — 전체 과정 
# ① Git 초기화
cd ~/projects/내프로젝트
git init

# ② .gitignore 직접 생성 (필수!)

# ③ 첫 커밋
git add .
git commit -m "Initial commit"

# ④ GitHub에서 빈 저장소 생성 (체크박스 모두 해제!)

# ⑤ 연결 & Push
git branch -M main
git remote add origin https://github.com/내이름/프로젝트.git
git push -u origin main
😱
만약 빈 저장소가 아닌 곳에 push 하려 하면?

error: failed to push some refs to... 또는 Updates were rejected because the remote contains work... 에러가 뜹니다. 이때는 GitHub 저장소를 삭제하고 빈 저장소로 다시 만들거나, git pull --rebase origin main 후 push하는 방법이 있습니다. 초보자라면 삭제 후 재생성이 더 안전합니다.

Chapter 04

최종 추천: 어떤 방법을 써야 할까?

결론부터 말씀드리겠습니다.

🏆 초보자에게는 방법 A (Remote-First)를 강력히 추천합니다

방법 A가 더 좋은 이유는 단순합니다 — 자동화된 부분이 많아서 실수할 여지가 적습니다.

git init, branch -M main, remote add origin 같은 초기 설정 명령어들은 초보자에게 혼란을 주기 쉽고, 하나라도 빠뜨리면 에러가 발생합니다. 반면 git clone 한 번이면 이 모든 것이 자동으로 설정됩니다.

🟢 방법 A를 쓸 때

새 프로젝트를 처음 시작할 때. 아직 코드를 한 줄도 안 짰을 때. Git/GitHub에 아직 익숙하지 않을 때. 팀 프로젝트를 시작할 때.

🟣 방법 B를 쓸 때

이미 코드가 상당량 작성된 프로젝트를 뒤늦게 GitHub에 올릴 때. 기존 폴더 구조를 그대로 유지하고 싶을 때.

✅ 가장 안전한 습관

프로젝트를 시작하기로 결심하면, 코드를 쓰기 전에 GitHub 저장소를 먼저 만들고 clone하세요. 이게 가장 깔끔합니다.

🔄 실전 꿀팁

방법 B를 알아야 하는 이유: 실무에서는 "일단 급하게 코딩부터 시작"하는 경우가 많습니다. 나중에 GitHub에 올려야 할 때 방법 B가 필요합니다.

📌
한 줄 요약

새 프로젝트 = 방법 A (GitHub 먼저 → Clone → 코딩)
기존 프로젝트에 GitHub 연결 = 방법 B (git init → 빈 Repo 생성 → remote add → push)
둘 다 알아두되, 가능하면 항상 방법 A로 시작하는 습관을 들이세요.

💬
참고: VS Code / Cursor 사용자라면

방법 A는 Clone Repository 버튼 한 번이면 끝입니다. 방법 B는 Initialize Repository → 소스 제어 탭 → Add Remote → Publish Branch까지 여러 단계를 거쳐야 합니다. GUI 환경에서도 방법 A가 훨씬 간편합니다.
