Git Diverge 완벽 가이드

로컬과 원격 브랜치가 갈라지는 현상(Diverge)은 왜 발생하고, 어떻게 해결하는지 단계별로 알아봅니다.

목차

01 Diverge란 무엇인가

Diverge는 영어로 "갈라지다"라는 뜻입니다. Git에서 Diverge란 로컬 브랜치와 원격 브랜치(origin)가 같은 커밋을 출발점으로 하여 각각 서로 다른 방향으로 새 커밋을 만들어 갈라진 상태를 말합니다.

공통 출발점 ↓ 로컬 main : A → B → C → E (내가 만든 커밋) origin/main : A → B → C → D (원격에 추가된 커밋) ↑ 여기서 갈라짐!

이때 git status를 실행하면 다음과 같은 메시지가 나옵니다:

$ git status On branch main Your branch and 'origin/main' have diverged, and have 1 and 1 different commits each, respectively.

02 Behind vs Diverge 차이

초보자가 가장 헷갈리는 부분입니다. "뒤처진(Behind)" 상태와 "갈라진(Diverge)" 상태는 완전히 다른 상황입니다.

🔹 Behind (뒤처진 상태)

원격에만 새 커밋이 추가되고, 로컬에서는 아무 커밋도 하지 않은 상태입니다. 히스토리가 직선이므로 충돌 없이 깔끔하게 합칠 수 있습니다.

로컬 main : A → B → C origin/main : A → B → C → D ↑ 이것만 받아오면 됨
Your branch is behind 'origin/main' by 1 commit, and can be fast-forwarded.

🔹 Diverge (갈라진 상태)

로컬과 원격 양쪽 모두 새 커밋이 추가된 상태입니다. 두 갈래를 합쳐야 하므로 추가 작업이 필요합니다.

로컬 main : A → B → C → E origin/main : A → B → C → D
Your branch and 'origin/main' have diverged, and have 1 and 1 different commits each.
핵심 차이

Behind는 git pull로 간단히 해결됩니다 (fast-forward). Diverge는 merge 또는 rebase로 두 갈래를 합쳐야 합니다. 파일 수정이 겹치면 충돌(conflict)이 발생할 수도 있습니다.

03 Diverge는 언제 발생하는가

Diverge가 발생하는 구체적인 과정을 단계별로 살펴보겠습니다.

1

초기 상태 — 로컬과 원격이 동일

나와 동료 모두 같은 커밋 C까지 작업이 완료된 상태입니다. 모든 것이 동기화되어 있습니다.

로컬 main : A → B → C origin/main : A → B → C ↑ 동일한 시점
2

원격에 새 커밋 추가

동료가 회원가입 버그를 수정하고 원격에 push합니다. 또는 GitHub에서 직접 파일을 수정할 수도 있습니다.

로컬 main : A → B → C origin/main : A → B → C → D (동료의 push)
3

로컬에서도 새 커밋 생성

나는 동료의 push를 모른 채 로그인 기능을 수정하고 커밋합니다. 이 순간 Diverge가 발생합니다.

로컬 main : A → B → C → E (내 커밋) origin/main : A → B → C → D (동료 커밋) ↑ 여기서 갈라짐!
!

Push 시도 → 거부됨

이 상태에서 git push를 하면 Git이 거부합니다. 먼저 원격의 변경사항을 받아와서 합쳐야 합니다.

$ git push ! [rejected] main -> main (fetch first) error: failed to push some refs to 'origin' hint: Updates were rejected because the remote contains work hint: that you do not have locally.
자주 발생하는 상황들

1. 팀원 여러 명이 같은 브랜치에서 작업할 때
2. GitHub에서 직접 파일을 수정(웹 에디터)한 뒤 로컬에서도 커밋했을 때
3. git pull 없이 오래 작업하다가 push 시도할 때
4. git commit --amend나 git rebase로 이미 push한 커밋을 수정했을 때

04 왜 Diverge가 허용되는가

Diverge는 "문제"가 아니라 팀으로 일할 때 자연스럽게 발생하는 현상입니다. 오히려 Git이 이를 허용하기 때문에 팀원들이 서로에게 영향을 주지 않고 독립적으로 작업할 수 있습니다.

Diverge가 가능한 이유 = Git의 핵심 장점

만약 Diverge가 허용되지 않는다면, 한 사람이 작업하는 동안 다른 사람은 아무것도 할 수 없을 것입니다. Git은 각자 자유롭게 작업하고 나중에 합치는 방식을 선택했기 때문에, 여러 사람이 동시에 같은 프로젝트를 효율적으로 개발할 수 있습니다.

실제 현업 시나리오를 생각해 봅시다:

나는 로그인 기능을 고치고, 동료 A는 회원가입을 수정하고, 동료 B는 UI를 개선합니다. 각자 독립적으로 커밋을 만들면 여러 갈래의 Diverge가 발생합니다. 하지만 이것은 문제가 아니라, 각자의 작업 영역이 보장된다는 뜻입니다. 작업이 끝나면 Git의 merge/rebase 기능으로 깔끔하게 합칠 수 있습니다.

05 Diverge 해결 방법

Diverge를 해결하는 방법은 크게 두 가지입니다. 각각 장단점이 있으니 상황에 맞게 선택하세요.

git pull

Merge 방식 (기본값)
A → B → C → D ─┐ └→ F (merge) A → B → C → E ─┘
  • 두 갈래를 합치는 병합 커밋(F) 이 자동 생성됨
  • 모든 히스토리가 그대로 보존됨
  • 히스토리가 복잡해질 수 있음
  • 초보자에게 추천 — 안전하고 직관적

git pull --rebase

Rebase 방식
변경 전: C → D (origin) C → E (local) 변경 후: A → B → C → D → E' (깔끔한 직선)
  • 내 커밋(E)을 원격 커밋(D) 뒤로 재배치
  • 히스토리가 깔끔한 직선이 됨
  • 커밋 해시가 바뀜 (E → E')
  • 충돌 해결이 조금 더 복잡할 수 있음

실행 명령어

// 방법 1: Merge (기본, 초보자 추천) $ git pull // 방법 2: Rebase (깔끔한 히스토리) $ git pull --rebase // 합친 후 원격에 반영 $ git push

06 충돌(Conflict) 해결하기

Diverge를 합칠 때, 로컬과 원격에서 같은 파일의 같은 부분을 수정했다면 Git은 자동으로 합칠 수 없어 충돌(Conflict)이 발생합니다.

$ git pull Auto-merging src/auth.ts CONFLICT (content): Merge conflict in src/auth.ts Automatic merge failed; fix conflicts and then commit the result.

충돌이 발생한 파일을 열면 다음과 같은 표시가 있습니다:

<<<<<<< HEAD const session = await getSession(); ← 내가 수정한 코드 ======= const session = await auth(); ← 원격의 코드 >>>>>>> origin/main

해결 순서

1

충돌 파일 열기

VS Code에서 충돌 파일을 열면 "Accept Current", "Accept Incoming", "Accept Both" 버튼이 표시됩니다. 원하는 코드를 선택하거나 직접 수정합니다.

2

수정 후 스테이징

충돌을 해결한 후 git add . 으로 수정된 파일을 스테이징합니다.

3

커밋 & 푸시

git commit으로 병합 커밋을 완성한 뒤 git push로 원격에 반영합니다.

// 충돌 해결 후 전체 흐름 $ git add . $ git commit -m "merge: resolve conflict in auth.ts" $ git push
팁: 충돌을 줄이려면

자주 pull 하세요. 작업 시작 전에 git pull을 습관처럼 실행하면, 원격과의 차이가 적어져서 Diverge 자체가 발생하기 어렵고, 발생하더라도 충돌 범위가 작아집니다.

// 1. 원격 변경사항 가져오기 $ git pull // 2. 작업하기 (코드 수정) // 3. 변경사항 커밋 $ git add . $ git commit -m "feat: 작업 내용 설명" // 4. 원격에 반영 $ git push
