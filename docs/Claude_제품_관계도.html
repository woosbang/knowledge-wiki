Claude 에이전트 제품 관계도

하나의 AI 엔진 위에 구축된 11개 제품의 관계를 이해하기 위한 가이드. 어떤 상황에서 어떤 Claude를 써야 하는지 한눈에 파악할 수 있습니다.

하나의 두뇌, 여러 개의 몸

Claude의 모든 제품은 하나의 AI 엔진(Claude Agent SDK)을 공유합니다. Opus 4.6, Sonnet 4.6, Haiku 4.5 모델이 모든 인터페이스에서 동일하게 작동합니다. 제품 간의 차이는 "어디서 실행되느냐"와 "무엇에 접근할 수 있느냐"에 있습니다.

비유하자면, 같은 요리사(Claude)가 주방 종류에 따라 다른 도구를 사용하는 것과 같습니다. 전문 주방에서는 모든 장비에 접근할 수 있고, 집 주방에서는 지정된 공간만 쓰고, 레스토랑 테이블에서는 눈앞의 접시만 다룹니다.

Architecture Overview

세계 1 — 코드를 짠다

소프트웨어를 만들고, 디버깅하고, PR을 올리는 세계입니다. 6개의 인터페이스가 하나의 코딩 에이전트를 서로 다른 환경에서 제공합니다.

제품설명실행 환경
CLI터미널에서 직접 명령하는 원본 도구. 시스템 전체 접근, 완전 자율 실행 가능.
Context rewind, 서브에이전트, 훅, Vim 모드 등 모든 기능 지원		로컬
VS Code ExtensionVS Code 사이드바에서 시각적으로 작업. 인라인 diff, 체크포인트, Plan 모드.
CLI와 설정 파일 공유. Cursor, Windsurf 등 포크도 지원		로컬
JetBrains PluginIntelliJ, PyCharm, WebStorm 등에서 사용. CLI 래퍼 방식으로 IDE 통합.
네이티브 diff 뷰어, 자동 코드 컨텍스트 인식		로컬
Code on the WebAnthropic 클라우드 VM에서 실행. 여러 작업 병렬 처리, 자동 PR 생성.
Teleport로 클라우드→로컬 세션 이동 가능. GitHub만 지원		클라우드
Desktop AppClaude Desktop 앱의 Code 탭. 시각적 diff 리뷰, 서버 프리뷰.
터미널 없이 GUI로 로컬 코딩		로컬
Remote Control로컬 CLI 세션을 폰/브라우저에서 이어서 작업. 코드는 내 컴퓨터에 유지.
자동 재연결, QR 코드 연결. 로컬 MCP 서버/환경변수 완전 유지		로컬 실행 원격 뷰

핵심 관계: 로컬 도구들(CLI, VS Code, JetBrains, Desktop)은 ~/.claude/settings.json을 공유하며 자유롭게 전환할 수 있습니다. Code on the Web은 클라우드 독립 실행이라 로컬 환경에 접근할 수 없지만, Teleport로 세션을 로컬로 가져올 수 있습니다. Remote Control은 이 둘의 장점을 결합합니다.

세계 2 — 일을 대신한다

코딩이 아닌 일반 업무를 자동화하는 범용 데스크톱 에이전트입니다.

Cowork 작업 흐름

CLI와의 관계: Cowork는 CLI와 같은 엔진을 사용하지만, 샌드박스(지정 폴더만 접근) 안에서 실행됩니다. CLI에서 할 수 없는 것(예약 작업, 커넥터, 플러그인)이 있고, Cowork에서 할 수 없는 것(시스템 전체 접근, git, 서버 실행)이 있습니다. 서로 다른 시나리오에 최적화된 형제 제품입니다.

세계 3 — 앱 안에서 돕는다

이미 사용 중인 앱 안에서 Claude가 직접 작동합니다. Cowork와 조합하면 연속 워크플로우를 만들 수 있습니다.

제품설명환경
Chrome브라우저에서 웹페이지 탐색, 클릭, 폼 작성, 정보 추출. 사용자 로그인 세션 공유.
Cowork 연동: Chrome이 리서치 → Cowork가 보고서 생성		브라우저
Excel워크북 전체(모든 탭, 수식, 셀 의존성) 인식. 셀 수준 인용으로 검증 가능.
수식 생성, 차트, 피벗 테이블 자동화		앱 내
PowerPoint슬라이드 마스터(템플릿, 폰트, 색상) 자동 인식. 브랜드 가이드라인 준수.
Excel→PPT 연동으로 분석 결과를 바로 발표자료로 전환		앱 내
SlackSlack 내에서 대화, 메시지 초안/미리보기/게시. 워크스페이스 검색 연동.
Interactive Apps(MCP Apps)로 Slack을 떠나지 않고 작업		Slack 앱
제품 간 연동 워크플로우

나는 어떤 Claude를 써야 할까?

의사결정 가이드

1
코딩 / 소프트웨어 개발 작업인가요?
예 → 로컬 환경이 필요한가요?
예 → 이동 중 작업?
예 → 📱 Remote Control
아니오 → ⌨️ CLI 또는 🖥️ IDE Extension
아니오 → ☁️ Code on the Web
2
파일 생성/정리/분석 등 업무 자동화인가요?
예 → 💼 Cowork
3
특정 앱에서 작업하나요?
브라우저 → 🌐 Chrome · 스프레드시트 → 📊 Excel · 발표자료 → 📊 PPT · 팀 소통 → 💬 Slack

세 가지 세계, 핵심 비교

🔧 개발자 도구

  • 시스템 전체 접근 (파일, 터미널, git)
  • 코드 작성, 디버깅, 테스트, PR 생성
  • 가장 높은 자유도와 제어력
  • 터미널/IDE 사용 능력 필요
  • 6개 인터페이스

💼 Cowork

  • 지정 폴더만 접근 (샌드박스)
  • 파일 정리, 리서치, 보고서, 분석
  • 예약 작업으로 자동 반복 실행
  • 커넥터 (Drive, Gmail 등)
  • 기술 지식 불필요

📎 앱 통합

  • 해당 앱/문서 범위에서만 작동
  • 이미 쓰는 앱에서 바로 사용
  • Cowork와 조합 시 연속 워크플로우
  • Chrome, Excel, PowerPoint, Slack
  • 설치 후 즉시 사용

자주 묻는 질문

CLI를 쓰고 있는데 VS Code Extension도 써야 하나요?▾
둘 다 쓸 수 있고, 실제로 많은 개발자가 그렇게 합니다. 설정 파일을 공유하므로 전환이 자연스럽습니다. 시각적 diff가 필요하면 Extension, 세밀한 제어가 필요하면 CLI를 쓰세요.
Cowork와 일반 Claude Chat은 뭐가 다른가요?▾
일반 Chat은 대화만 합니다. Cowork는 실제로 실행합니다 — 파일을 만들고, 수정하고, 외부 서비스에서 데이터를 가져오고, 결과물을 전달합니다. 예약 작업으로 자동 실행도 가능합니다.
Code on the Web과 Remote Control은 언제 뭘 쓰나요?▾
Code on the Web은 로컬에 레포가 없거나 여러 작업을 병렬로 돌리고 싶을 때. Remote Control은 이미 로컬에서 작업 중이고 자리를 비우면서 폰으로 모니터링하고 싶을 때 사용합니다.
비개발자인데 뭘 써야 하나요?▾
대부분 Cowork만으로 충분합니다. 여기에 Chrome, Excel, PowerPoint 통합을 조합하면 더욱 강력해집니다. 코딩 도구는 소프트웨어 개발 작업에만 필요합니다.
Cowork로 CLI의 모든 작업을 할 수 있나요?▾
아닙니다. Cowork는 샌드박스에서 실행되므로 시스템 전체 제어가 불가합니다. 반면 Cowork에만 있는 기능(예약 작업, 커넥터, 플러그인)도 있습니다. 서로 다른 시나리오에 최적화된 형제 제품입니다.
