Chapter 1

왜 혼동 행렬이 필요한가?

단순 정확도의 함정

분류 모델을 평가할 때 가장 먼저 떠올리는 지표는 정확도(Accuracy)입니다. "전체 예측 중 맞은 비율"이라는 직관적 정의 덕분에 이해하기 쉽지만, 현실의 데이터는 대부분 클래스 불균형(Class Imbalance) 상태이기 때문에 정확도만으로는 모델의 진짜 성능을 판단할 수 없습니다.

예시 — 암 검진 시스템
전체 환자 1,000명 중 실제 암 환자가 10명(1%)이라고 가정합니다. 모델이 모든 환자를 "정상"이라고 예측하더라도 정확도는 99%입니다. 하지만 이 모델은 단 한 명의 암 환자도 찾아내지 못했으므로 실질적으로 쓸모가 없습니다.

이처럼 정확도는 다수 클래스에 치우친 예측을 높은 점수로 보상하는 맹점이 있습니다. 이 문제를 해결하기 위해, 모델이 어떤 유형의 정답과 오답을 만들어냈는지를 구조적으로 분해하는 도구가 바로 혼동 행렬(Confusion Matrix)입니다.

혼동 행렬의 탄생 배경

혼동 행렬은 통계학과 신호 탐지 이론(Signal Detection Theory)에서 유래했습니다. 제2차 세계대전 당시 레이더 신호를 분석하면서, "실제로 적기가 있는데 놓친 경우"와 "적기가 없는데 경보를 울린 경우"를 구분해야 할 필요성에서 이 개념이 체계화되었습니다. 이후 의학 진단, 정보 검색, 머신러닝 등으로 확산되어 오늘날 모든 분류 문제의 표준 평가 프레임워크로 자리잡았습니다.

핵심 아이디어

혼동 행렬의 핵심은 단 하나의 질문입니다: "모델의 예측과 실제 정답이 어떻게 교차하는가?" 이 교차점을 2×2 격자로 시각화하면, 모델이 만들어내는 네 가지 결과 유형을 한눈에 파악할 수 있습니다.

혼동 행렬의 구조

이진 분류(Binary Classification)에서 혼동 행렬은 아래와 같이 2×2 격자로 구성됩니다. 행(row)은 실제 값을, 열(column)은 모델의 예측 값을 나타냅니다.

모델 예측 (Predicted)
Positive
Negative
실제 값 (Actual)
TP 참 양성
FN 거짓 음성 (2종 오류)
FP 거짓 양성 (1종 오류)
TN 참 음성

암기 요령: 앞 글자 = 정답 여부, 뒷 글자 = 모델 예측

TP, FP, TN, FN이라는 약어에서 첫 글자(T/F)는 "모델이 맞았는가 틀렸는가"를, 뒷 글자(P/N)는 "모델이 뭐라고 예측했는가"를 나타냅니다.

약어의미출입문 예시
TP 맞았다(T) + Positive로 예측 출입 허가 → 실제 등록자 ✓
FP 틀렸다(F) + Positive로 예측 출입 허가 → 실제 미등록자 ✗ 1종 오류
TN 맞았다(T) + Negative로 예측 출입 거부 → 실제 미등록자 ✓
FN 틀렸다(F) + Negative로 예측 출입 거부 → 실제 등록자 ✗ 2종 오류
Chapter 3

혼동 행렬 기반 평가지표

분모가 누구 기준이냐로 구분

지표들이 헷갈리는 가장 큰 이유는 공식이 비슷하게 생겼기 때문입니다. 핵심은 분모를 누구 기준으로 잡느냐입니다. Precision은 "모델이 양성이라고 예측한 것들" 중에서 계산하고, Recall/민감도는 "실제로 양성인 것들" 중에서 계산합니다.

지표공식핵심 암기법
정확도
Accuracy		 (TP+TN) / 전체 전체 중 맞은 비율. 클래스 불균형 시 신뢰도 하락에 주의
정밀도
Precision		 TP / (TP+FP) "모델 기준" — 양성 예측 중 진짜 양성 비율 → 정확성
민감도 = 재현율
Sensitivity = Recall = TPR		 TP / (TP+FN) "현실 양성 기준" — 실제 양성 중 찾아낸 비율 → 완전성
특이도
Specificity = TNR		 TN / (TN+FP) "현실 음성 기준" — 실제 음성 중 올바르게 거부한 비율 → 차단력
F1-Score 2×P×R / (P+R) 정밀도와 재현율의 조화 평균 → 균형

민감도 vs 특이도: 거울 관계

민감도와 특이도는 서로 대칭적인 관계입니다. 둘 다 분모가 "현실 기준"이지만, 민감도는 양성(P) 쪽을, 특이도는 음성(N) 쪽을 바라봅니다.

민감도가 높으면?

"직원은 무사 통과!"

→ 실제 양성을 놓치지 않음

특이도가 높으면?

"외부인은 확실히 차단!"

→ 실제 음성을 정확히 걸러냄

Precision과 특이도의 차이
특이도는 "실제 음성(N) 중 올바르게 거부한 비율"이고, Precision은 "모델이 양성(P)이라 예측한 것 중 실제 양성 비율"입니다. 분모의 기준이 다르다는 점을 기억하면 구분할 수 있습니다.

가설검정의 1종·2종 오류와의 연결

통계학의 가설검정(Hypothesis Testing)에서 말하는 1종 오류, 2종 오류는 혼동 행렬의 FP, FN과 정확히 대응됩니다. 출입문 시스템에 비유하면, 귀무가설(H₀)은 "이 사람은 미등록자이다"—즉, 문이 잠겨 있는 기본 상태입니다.

귀무가설(H₀): "이 사람은 미등록자이다" ← 출입문은 기본적으로 잠김(거부)이 기본 상태
오류 유형혼동행렬통계적 의미출입문 예시
1종 오류
Type I · α		 FP H₀가 참인데 기각
미등록자인데 등록자로 판정		 도둑에게 문을 열어줌
→ 보안 사고!
2종 오류
Type II · β		 FN H₀가 거짓인데 채택
등록자인데 미등록자로 판정		 직원인데 문이 안 열림
→ 직원 불만!

오류와 지표의 관계

어떤 오류를 줄이느냐에 따라 올려야 할 지표가 달라지고, 이는 모델의 임계값(Threshold) 조정으로 제어합니다. 그러나 두 오류는 상충 관계에 있어, 하나를 줄이면 다른 하나가 커지는 트레이드오프가 발생합니다.

줄이고 싶은 것높여야 할 지표해석
1종 오류 (FP) 특이도 ↑ 또는 정밀도 ↑ 외부인 차단 강화 → 보안 강화 (임계값을 높이면 달성)
2종 오류 (FN) 민감도(Recall) ↑ 직원 통과율 향상 → 편의성 증가 (임계값을 낮추면 달성)
트레이드오프의 핵심
임계값을 높이면 → 모델이 "양성"이라 판단하는 기준이 엄격해짐 → FP↓ 하지만 FN↑
임계값을 낮추면 → 모델이 "양성"이라 판단하는 기준이 느슨해짐 → FN↓ 하지만 FP↑
이 균형점을 찾기 위해 ROC 곡선과 EER(Equal Error Rate) 등의 도구를 사용합니다.
Chapter 5

실전 활용 사례

같은 혼동 행렬이라도 도메인에 따라 어떤 오류가 더 치명적인지가 완전히 달라집니다. 이 차이가 곧 "어떤 지표를 우선시해야 하는가"를 결정합니다.

Case Study 01

안면인식 출입문 시스템

상황 설정: 회사 건물에 안면인식 출입문을 설치합니다. 카메라가 얼굴을 인식하고, 등록된 직원이면 문을 열고(Positive), 미등록자이면 문을 잠급니다(Negative).

1종 오류 (FP) — 보안 사고

미등록자를 직원으로 잘못 인식하여 문이 열립니다. 비인가자가 사내에 침입할 수 있어 물리적 보안이 무너집니다.

→ 군사시설·데이터센터에서는 절대 허용 불가

2종 오류 (FN) — 직원 불편

등록된 직원인데 미등록자로 판정되어 문이 안 열립니다. 매번 수동 인증을 거쳐야 하므로 업무 효율이 떨어집니다.

→ 잦으면 시스템 신뢰도 자체가 하락

환경우선 지표임계값 전략이유
군사·기밀시설 특이도 / 정밀도 최우선 매우 높게 비인가 침입 시 피해가 극심하므로 FP를 극도로 억제
일반 사무실 F1-Score 균형 EER 부근 보안과 편의성 사이의 합리적 균형점 선택
편의시설·공유오피스 민감도(Recall) 우선 낮게 이용자 불편을 최소화하는 것이 사업적으로 더 중요
실무 참고 — FAR과 FRR
안면인식 업계에서는 FP 비율을 FAR(False Acceptance Rate, 오수락률), FN 비율을 FRR(False Rejection Rate, 오거부율)이라는 고유 명칭으로 사용합니다. FAR = 1 − 특이도, FRR = 1 − 민감도의 관계에 있습니다.
Case Study 02

의료 진단 — 암 검출 AI

상황 설정: AI 시스템이 CT 영상을 분석하여 폐암 의심 여부를 판정합니다. 양성(Positive)은 "암 의심", 음성(Negative)은 "정상"을 의미합니다.

2종 오류 (FN) — 생명 위협

실제 암 환자를 "정상"으로 판정합니다. 환자는 치료 시기를 놓치게 되며, 생명과 직결되는 치명적 오류입니다.

→ 의료 분야에서 가장 위험한 오류

1종 오류 (FP) — 불필요한 검사

정상인을 "암 의심"으로 판정합니다. 불필요한 정밀 검사, 환자의 정신적 불안, 의료 비용 증가 등이 발생합니다.

→ 부담이 크지만 생명 위협보다는 낮음

핵심 — 의료에서는 민감도(Recall)가 최우선
의료 진단에서 "놓침(FN)"은 곧 환자의 생명 위험입니다. 따라서 민감도를 최대한 높여 암 환자를 단 한 명도 놓치지 않는 것이 첫 번째 목표입니다. 그 대가로 FP(위양성)가 늘어나더라도, 추가 정밀 검사를 통해 걸러낼 수 있으므로 상대적으로 허용 가능합니다. 이것이 의료 AI에서 민감도를 우선시하는 이유입니다.
진단 단계우선 지표이유
1차 스크리닝 (선별 검사) 민감도(Recall) 최우선 한 명도 놓치지 않는 것이 목표 → FN 최소화
2차 정밀 검사 특이도 / 정밀도 강화 1차에서 걸러진 의심 환자 중 진짜 환자를 정확히 확인 → FP 최소화

이처럼 의료 시스템은 흔히 2단계 구조로 설계됩니다. 1차에서 민감도 중심으로 광범위하게 걸러낸 후, 2차에서 특이도와 정밀도 중심으로 정밀하게 확인하는 방식입니다. 이는 안면인식 출입문이 보안(특이도)을 우선시하는 것과 정반대의 전략이며, 도메인에 따라 지표 우선순위가 달라지는 대표적 사례입니다.
